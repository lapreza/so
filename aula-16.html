Sistemas Operacionais Distribuídos: Princípios, Transparência e Arquiteturas

Estudo da integração de múltiplos computadores autônomos em um sistema único e coeso, dimensões de transparência, modelos de middleware e sistemas de arquivos distribuídos.

1. O que é um Sistema Operacional Distribuído?

Um Sistema Distribuído é uma coleção de computadores independentes interconectados por uma rede que se apresenta aos seus usuários como um único sistema computacional coerente e integrado (Coulouris et al.; Tanenbaum).

Enquanto num Sistema Operacional de Rede (NOS) o usuário precisa ter consciência explícita de quais máquinas está acessando (ex: conectando via SSH ou FTP), num **Sistema Operacional Distribuído (DOS)** a gestão de recursos (CPU, memória e arquivos) é realizada pelo núcleo de forma totalmente transparente e global.

2. Requisitos e Dimensões de Transparência

O objetivo central de um SO Distribuído é ocultar a natureza distribuída da sua infraestrutura física. A literatura estabelece as seguintes formas de transparência:

Transparência de Localização: Os usuários não conseguem identificar onde os recursos físicos (arquivos, processos ou hardware) estão fisicamente armazenados.
Transparência de Acesso: Recursos locais e remotos são acessados através exatamente dos mesmos comandos e interfaces de programação (APIs).
Transparência de Migração e Mobilidade: Recursos podem ser movidos livremente entre nós físicos da rede sem alterar a forma como são referenciados pelas aplicações.
Transparência de Replicação: O sistema pode manter múltiplas cópias redundantes de arquivos ou dados para aumentar a disponibilidade sem que o usuário saiba qual cópia está acessando.
Transparência a Falhas (Fault Tolerance): Módulos de software e aplicações continuam a executar sem interrupção mesmo se um nó de hardware na rede falhar.

3. Modelos de Arquitetura e Middleware

A organização de sistemas distribuídos modernos divide-se em três modelos principais:

Cliente-Servidor (Client-Server)

Processos clientes enviam requisições de serviço para processos servidores centralizados ou distribuídos que processam e retornam o resultado.

Ponto a Ponto (Peer-to-Peer - P2P)

Todos os nós da rede possuem capacidades e responsabilidades idênticas, atuando simultaneamente como clientes e servidores de dados.

Arquitetura baseada em Middleware

Camada de software colocada sobre sistemas operacionais heterogêneos para fornecer abstração de RPC (Remote Procedure Call) e mensagens.

4. Sistemas de Arquivos Distribuídos (DFS)

Um **DFS (Distributed File System)** permite que clientes acessem arquivos armazenados em servidores remotos exatamente da mesma forma que acessam arquivos em seus discos locais.

Exemplos clássicos e modernos incluem o NFS (Network File System) do ecossistema Unix/Linux, o protocolo SMB/CIFS para ambientes Windows, e o HDFS (Hadoop Distributed File System) projetado para alta vazão no processamento de Big Data.

5. Questões para Fixação e Discussão

Questão 1:

Diferencie um Sistema Operacional de Rede (NOS) de um Sistema Operacional Distribuído (DOS) quanto à visibilidade das máquinas remotas para o usuário.

Questão 2:

Explique por que a Transparência de Acesso e a Transparência de Localização são consideradas os dois pilares fundamentais de um Sistema de Arquivos Distribuído (DFS) como o NFS.
