Ambiente CLI (Linux/Windows) e Chamadas de Sistema (System Calls)

Estudo da interface de linha de comandos (CLI), a mecânica de transição do Modo Usuário para o Modo Kernel via chamadas de sistema e a utilização de APIs padrão (POSIX e Win32/Win64).

1. A Interface de Linha de Comandos (CLI)

A CLI (Command Line Interface), ou intérprete de comandos (Shell), é a interface textual que permite ao usuário interagir diretamente com o Sistema Operacional através de comandos digitados. Diferente da GUI (Interface Gráfica), a CLI consome poucos recursos de memória e CPU, além de permitir a automação completa de tarefas por meio de *scripts*.

No Linux, o shell padrão mais comum é o Bash (Bourne Again Shell), enquanto no ecossistema Windows destacam-se o Prompt de Comando (cmd.exe) e o PowerShell.

2. Chamadas de Sistema (System Calls)

As System Calls (Syscalls) constituem a interface programática formal que os programas em execução no Modo Usuário utilizam para solicitar serviços privilegiados ao Modo Kernel do Sistema Operacional (como ler um ficheiro no disco, alocar memória física ou enviar dados pela rede).

Mecanismo de Transição de Modo (Trap/Interrupt)

Quando um processo necessita de um serviço do kernel:

  1. O programa carrega os parâmetros da chamada de sistema nos registradores do processador.
  2. Executa uma instrução especial de interrupção por software (ex: sysenter, syscall ou INT 0x80).
  3. A CPU altera o modo de execução de Modo Usuário (User Mode) para Modo Kernel (Kernel Mode).
  4. O Kernel busca a chamada na tabela de interrupções, valida os parâmetros e executa o serviço de forma segura.
  5. A CPU retorna o resultado e altera o estado de volta para o Modo Usuário.

3. Categorização das Chamadas de Sistema

As System Calls são agrupadas de acordo com o subsistema do núcleo que é invocado:

Categoria Função Principal Exemplo POSIX (Linux/Unix) Exemplo Win32 (Windows)
Controle de Processos Criar, finalizar ou aguardar a execução de processos. fork(), exec(), exit() CreateProcess(), ExitProcess()
Manipulação de Arquivos Abrir, ler, escrever e fechar arquivos ou diretórios. open(), read(), write(), close() CreateFile(), ReadFile(), WriteFile()
Gerenciamento de Dispositivos Solicitar acesso exclusivo, ler/escrever em periféricos. ioctl(), read(), write() DeviceIoControl()
Manutenção de Informações Obter data, hora, dados do sistema e estatísticas de uso. getpid(), time(), alarm() GetSystemTime(), GetCurrentProcessId()
Comunicação e Redes Criar conexões de rede, enviar/receber dados via sockets. socket(), bind(), connect() WSAStartup(), socket()

4. A Relação entre APIs e System Calls

Na prática, a maioria dos programadores não invoca System Calls diretamente. Em vez disso, utilizam **APIs (Application Programming Interfaces)** como a **libc (POSIX)** em C/C++ ou as bibliotecas padrão do Python, Java e C#.

A função printf() da linguagem C, por exemplo, não é uma chamada de sistema. Ela é uma função de biblioteca que formata o texto na RAM e, internamente, invoca a System Call write() do sistema operacional para enviar os caracteres à tela.

Portabilidade via API

Ao usar APIs padrão (ex: POSIX), o mesmo código-fonte C pode ser compilado no Linux, macOS ou BSD sem alterações, pois a biblioteca cuida de traduzir a chamada para a System Call específica de cada kernel.

Inspeção de Chamadas (strace / truss)

No Linux, é possível rastrear todas as System Calls executadas por um programa em tempo real utilizando o utilitário de linha de comando strace <nome_do_programa>.
