Memória Virtual, Algoritmos de Substituição de Páginas e Thrashing

Estudo da abstração de memória virtual por paginação por demanda, tratamento de faltas de página (Page Faults), algoritmos de substituição e colapso de desempenho por Thrashing.

1. O Conceito de Memória Virtual

A Memória Virtual é uma técnica que separa o espaço de endereçamento lógico visto pelo programa da memória física (RAM) realmente disponível. Ela permite a execução de processos que não estejam totalmente carregados na RAM, possibilitando rodar aplicações cujo tamanho excede a capacidade física instalada.

O mecanismo mais comum é a Paginação por Demanda (Demand Paging): as páginas só são trazidas da memória secundária (disco/SSD) para a RAM no momento exato em que são referenciadas pela CPU.

2. O Mecanismo de Falta de Página (Page Fault)

Na Tabela de Páginas, cada entrada possui um Bit de Validade (Valid/Invalid Bit). Se a CPU tenta acessar uma página cujo bit indica que ela não está na RAM, a MMU gera uma interrupção especial de hardware chamada Page Fault (Falta de Página).

Ciclo de Tratamento de um Page Fault

  1. A instrução tenta acessar a página virtual não mapeada na RAM.
  2. A MMU intercepta a falha e gera uma armadilha (*trap*) para o Sistema Operacional.
  3. O SO suspende o processo e verifica se a referência de endereço é válida no disco.
  4. O SO localiza uma moldura (*frame*) livre na RAM (se não houver, invoca um algoritmo de substituição).
  5. Inicia uma operação de E/S de disco para carregar a página na moldura alocada.
  6. Atualiza a Tabela de Páginas (altera o bit para válido) e reinicia a instrução interrompida da CPU.

3. Algoritmos de Substituição de Páginas

Quando ocorre um Page Fault e não existem molduras de página livres na RAM, o SO precisa selecionar uma página "vítima" na memória física para ser removida (ou gravada de volta no disco se tiver sido modificada — *dirty bit*).

1. Algoritmo Ótimo (OPT / MIN)

Substitui a página que não será utilizada pelo maior período de tempo no futuro. É um algoritmo teórico inalcançável na prática (exige conhecimento do futuro), utilizado como métrica de comparação.

2. FIFO (First-In, First-Out)

Substitui a página que está há mais tempo na RAM. Pode sofrer da Anomalia de Belady, onde aumentar o número de molduras de página alocadas pode paradoxalmente aumentar a taxa de Page Faults.

3. LRU (Least Recently Used)

Substitui a página que não é utilizada há mais tempo no passado recente (baseado na localidade temporal). Oferece excelente desempenho, mas exige suporte de hardware (pilha ou contadores de relógio).

4. Segunda Chance / Relógio (Clock Algorithm)

Aproximação prática do LRU com baixo custo. Utiliza uma lista circular de páginas e um bit de referência. Se a página selecionada tem bit 1, recebe uma segunda chance (bit vira 0) e o ponteiro avança.

4. Hiperatividade de Memória (Thrashing)

Se um processo não possui o número mínimo de molduras necessárias para manter o seu conjunto de trabalho (*Working Set*), a taxa de falhas de página dispara acentuadamente.

O Thrashing (Hiperatividade) é o estado crítico no qual o sistema passa mais tempo realizando operações de E/S de troca de páginas (*paging/swapping*) do que efetivamente executando instruções das aplicações, levando ao colapso do desempenho do sistema operacional.

5. Comparativo de Algoritmos de Substituição

Algoritmo Critério de Remoção Complexidade / Custo Anomalia de Belady?
Ótimo (OPT) Uso no futuro mais distante Teórico (Impossível) Não
FIFO Página mais antiga na RAM Muito Baixo (Fila simples) Sim
LRU Menos usada recentemente Alto (Exige suporte de HDW) Não
Relógio (Clock) Aproximação do LRU via bit de uso Baixo (Lista circular) Não
