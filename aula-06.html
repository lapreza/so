Threads, Concorrência e Programação Concorrente

Estudo do conceito de Threads (processos leves), diferenças entre concorrência e paralelismo, modelos de implementação de threads e desafios na programação concorrente.

1. O Conceito de Thread (Processo Leve)

Uma Thread (ou linha de execução) é a menor unidade de código que pode ser gerenciada e agendada pelo Sistema Operacional. Enquanto um processo tradicional encapsula o espaço de endereçamento de memória e os recursos do sistema, uma thread representa um fluxo de execução dentro desse processo.

Em um processo multithreaded, múltiplas threads compartilham o mesmo código, a mesma seção de dados e os recursos do sistema (como arquivos abertos), mas cada thread possui seu próprio Contador de Programa (PC), conjunto de Registradores e **Pilha de Execução (Stack)**.

2. Diferenças entre Processos e Threads

Característica Processo Thread
Espaço de Memória Isolado e protegido (cada processo possui seu próprio espaço virtual). Compartilhado entre todas as threads do mesmo processo.
Custo de Criação e Troca Elevado (exige alocação de tabelas de páginas e estruturas pesadas). Baixo (troca de contexto mais rápida e leve).
Comunicação (IPC) Requer mecanismos formais (pipes, sockets, memória compartilhada). Direta via variáveis globais e ponteiros na memória compartilhada.
Impacto em Caso de Falha Se um processo falha, os outros processos não são afetados. Se uma thread causa uma falha fatal (ex: *segmentation fault*), todo o processo é encerrado.

3. Concorrência vs. Paralelismo

Embora frequentemente utilizados como sinônimos, **concorrência** e **paralelismo** são conceitos distintos em arquitetura de sistemas operacionais:

Concorrência

Trata da capacidade de gerenciar e estruturar múltiplas tarefas que fazem progresso em intervalos de tempo sobrepostos. Em um sistema com apenas **um único núcleo de CPU**, a concorrência é obtida alternando rapidamente a execução das tarefas (*interleaving* ou fatia de tempo).

Paralelismo

Trata da capacidade de executar fisicamente duas ou mais instruções ao **mesmo tempo**. O paralelismo requer obrigatoriamente um hardware multicore (múltiplos núcleos de processamento ou múltiplos processadores físicos).

4. Modelos de Implementação de Threads

O mapeamento entre as threads criadas no nível da aplicação (User Threads) e as threads gerenciadas pelo núcleo do Sistema Operacional (Kernel Threads) pode seguir três modelos clássicos:

Modelo N:1 (Muitos para Um / User-Level Threads) Múltiplas threads de usuário são mapeadas para uma única thread de kernel. O gerenciamento é feito totalmente por uma biblioteca em espaço de usuário sem suporte direto do SO. Desvantagem: Se uma thread bloquear para E/S, todo o processo bloqueia.
Modelo 1:1 (Um para Um / Kernel-Level Threads) Cada thread de usuário corresponde diretamente a uma thread de kernel. É o modelo padrão adotado pelos sistemas operacionais modernos (Linux, Windows, macOS). Permite uso real de múltiplos núcleos de CPU.
Modelo M:N (Muitos para Muitos / Modelo Híbrido) Múltiplas threads de usuário são multiplexadas para um número igual ou menor de threads de kernel, combinando o baixo custo das user threads com o paralelismo das kernel threads.

5. Questões para Fixação e Discussão

Questão 1:

Explique por que a comunicação entre duas threads do mesmo processo é significativamente mais rápida do que a comunicação entre dois processos distintos no mesmo Sistema Operacional.

Questão 2:

Diferencie concorrência de paralelismo. É possível ter concorrência em um sistema com um único processador (*single-core*)? Justifique sua resposta.
